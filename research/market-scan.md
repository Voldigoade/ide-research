# Market scan and candidate decisions

The previous approximately 40-candidate scan and source register are retained. This pass revisits products that could have been excluded too quickly, checks official release/product evidence current to 2026-10-15, and replaces one generic framework finalist with a concrete editor whose maintained packages cover more of the requested stack.

## Updated shortlist (12)

| Candidate | Why it earns a final place | Main limit in this profile |
|---|---|---|
| Visual Studio Code | Broad Rust, Tauri, TypeScript, Python, remote, WSL, containers and agent ecosystem; strong AI-off usefulness | Extension and Microsoft-service trust boundaries; performance varies with workspace/extensions |
| IntelliJ IDEA Ultimate 2026.2 | Official Rust and Python plugins can coexist with web, database, Docker, Dev Containers, WSL, remote and Git; strongest JetBrains polyglot combination | Commercial; setup and profiling differences versus RustRover/PyCharm; local models do not run agents |
| RustRover 2026.2 | Most focused Rust/Cargo engine and debugger for Rust/Tauri-heavy work | Weaker verified fit for Python and full Next.js workflow |
| PyCharm Professional | Deep Python debugger, inspections, refactoring, DB and remote tooling | Rust is secondary; commercial tier for several professional functions |
| VSCodium | GUI Code OSS workflow with community build and Open VSX; privacy/local-control option | Open VSX and Microsoft Marketplace/service compatibility are not equivalent |
| Cursor 2.x | Complete VS Code-derived editing environment with integrated agents, models and worktrees | Proprietary service, usage limits, cloud terms and provider dependence |
| Zed 1.22 | Native editor, local model options, remote/agent protocols, Windows and Linux support | Database/container depth and Windows/WSL reports remain weaker |
| Neovim 0.12 | Mature configurable terminal IDE path with LSP and a fully local core | Requires 8-12 individually maintained components and user configuration |
| Sublime Text 4 Build 4213 | Cross-platform mature editor; Package Control currently has Rust/TS LSP and DAP/Python-debug packages; built-in terminal | Plugins do not supply first-party WSL/Dev Containers/remote workspace or complete IDE database tooling |
| Devin Desktop | Real VS Code-derived editor, source control and agent workflow, not an agent-only CLI | Agent/service terms, cost, privacy, extension and cross-platform evidence require plan-specific checks |
| Kiro 1.3.0 | Complete Code OSS-derived editor with spec workflow, extension system and agent features | AWS/provider dependence and a patched historical agentic-write advisory; current version is later than fix |
| Google Antigravity | Standalone agentic editor with extension support and a full editing surface | Newer product, thinner cross-platform maturity and privacy/terms evidence |

JetBrains Air is assessed as an agentic layer, not an extra editor finalist. The standalone Air system spans JetBrains IDEs, web, CLI and mobile surfaces, while Air in IDEs is an early-access plugin as of 2026-10-15. Its own evidence describes agent sessions, not a new Rust/Python/TypeScript code engine. It is counted in IDEA's agent configuration, avoiding a duplicate finalist for the same underlying IDE.

Eclipse Theia stays in the screened candidate pool but is removed from this final 12: it is an extensible IDE framework/distribution family, not one fixed application with one stable capability/licensing/support profile. A specific Theia distribution could merit another comparison if self-hosting or web IDE deployment is central. Sublime Text is a more concrete installable product for this user's local desktop choice.

## Agentic products as complete environments

Cursor, Devin Desktop, Kiro, and Antigravity remain distinct finalists because each has an actual editor surface, source control/editing workflow, and agent product. For each, the agent matrix scores Rust, Python, TS/React, Git, debugger, extensions, WSL/remote, platform support, AI-off usefulness, privacy, terms, and maturity. Product architecture or vendor marketing alone does not establish a language engine or performance.

The update changes JetBrains specifically: IDEA now supports a strong agent stack through AI Assistant and the Air in IDEs EAP, plus external Codex/Claude workflows, MCP and Copilot. Air's local-agent execution does not mean every model runs locally; Air relies on the chosen agent/provider and permissions.

## Community field reports used as leads

For the current top five, the retained field sample includes Rust developers comparing RustRover/VS Code, Python users describing PyCharm-to-VS Code migration and the reverse intent, 2026 PyCharm/VS Code discussions, Neovim users reporting VS Code migrations, and reports about Zed. The reports consistently describe trade-offs: refactoring/debugger integration versus editor startup and memory, a cohesive built-in workflow versus extension/UI setup, and local customization versus time to configure. They are self-selected posts and issues, not vote counts, controlled tests, or population prevalence. VSCodium-specific user migration evidence remains sparse; its ranking rests more on build/marketplace/privacy documentation than on a large field sample.

The date and URLs for all primary sources and selected field reports are in `evidence-register.md`. Scope notes and confidence limits are in `methodology.md` and `security-privacy.md`.
